# Build0.0.6: bounded host dice and private history

Implement the next authorized T013 increment under master-plan§0.1: browser-only DM/player app, independent Rust host, no public action or desktop shell. The saved0.0.5 source was restored before extending it. Source remains developer-built; final installation-free host packaging is a later acceptance gate.

Use a small typed AST in hearth-domain, not JavaScript eval or an external rules engine. Alternatives considered: client rolls cannot enforce authoritative results/privacy; a general scripting language adds an unnecessary execution boundary. Existing transactional WS commands and current filtered snapshots suit this bounded first dice slice. My default is public, DM+roller, self-only and blind(DM-only) scopes. Selected-recipient rolls will join chat/whispers in T014; advanced keep/drop/reroll/explode/Fate/pools remain P1. These partial features stay IN_PROGRESS.

Grammar: ASCII integer constants, NdM (also d20/D20), unary +/-, parentheses and +,-,*,/ with normal precedence. Expressions<=120bytes; <=64 AST nodes, <=12 nested parentheses/unary levels, <=100 dice total, 1..1000000 sides/constants. Finite arithmetic with absolute value<=1000000000; division by zero/overflow fails. Fractions are recorded as finite f64, rounded only in the UI. Record original trimmed expression, normalized expression/AST, all faces/subtotals, final total, roller identity/name, scope, server time and campaign revision. Secure host entropy uses OsRng.try_fill_bytes with rejection sampling; entropy failure aborts instead of panicking. Tests use an injected sampler, not seeded production RNG.

Strict dice.roll payload={clientRollId,expression,visibility:public|gm|self|blind}. Every role may roll; server derives roller/name/time/results. Existing request/base revision, membership/session, archive and atomic receipt/event boundaries apply. Duplicate accepted requests never reroll. Client nonces are unique only within campaign/roller; the host assigns separate result UUIDs, so creation never probes another caller’s hidden record. Limit10 accepted rolls per10seconds per user/campaign across connections. Keep the latest1000 persisted rolls per campaign; current projections contain only the latest20 authorized results. Receipt retention remains seven days/10000 revisions; stale old requests cannot execute again after pruning.

Scope is immutable. public: current campaign members; gm: current DMs and roller; self: roller only (other DMs excluded); blind: current DMs only, including no result/roll DTO for the player roller. A blind roller gets the same content-free acceptance acknowledgement as other commands and a local explanatory status. No result/faces/expression is put in event payloads: roll events are snapshot markers and each snapshot/REST read projects current permission before serialization. GET /rolls and /rolls/{rollId} share the authorized read transaction; hidden/unknown/foreign details are indistinguishable404. Reconnect/revocation clears/refreshes roll cache. Self rolls are private from other browser roles, not from the trusted host's physical database owner.

Migration0006 adds dice_rolls and independent short-lived rate timestamps; never edit older migrations. No new runtime dependency. Current snapshots must still fit512KiB with bounded history plus maximum actor/mask fixtures. No history editing/reveal/deletion UI yet; no cryptographic fair-roll proof against a malicious host.

UI: Dice dock tab, expression input and examples/limits/error feedback, four explicit visibility choices with scope-specific submit label, one-click standard dice using the selected scope, compact persisted recent results with roller/normalized expression/faces/total/scope/time. Busy/offline/archive disables submission. Local pending acceptance is distinct from a saved visible result.
