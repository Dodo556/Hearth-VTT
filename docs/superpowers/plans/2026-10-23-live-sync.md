# Live tabletop synchronization implementation plan

> Execute inline with test-first checks and one fresh whole-change review. The user explicitly authorized continuing the staged master plan.

**Goal:** Deliver T008 plus owned movement/visibility of the existing sample tokens, proving the protocol through real browser interaction.
**Architecture:** One authoritative Rust server, SQLite transactions/revisions/receipts, versioned authenticated WebSockets, filtered initial/reconnect snapshots and ordered small live events. Preserve the browser-only direction.
**Spec:** Master plan §§4–5/14/16/19–21, ADR-0002 and NEXT_TASKS T008–T011. General map uploads and actor authoring remain the next slice.

## Global constraints

- Origin/session/membership checks apply to handshakes, every command and outgoing changes; no client role or event claims are trusted.
- Persist before event/ack; duplicate accepted requests cannot mutate twice. Reused IDs with different bodies fail. Reject stale revisions and out-of-bounds movement.
- Never send private token data/art to players. Revocation clears browser state and closes subscriptions. Reconnect always uses a newly authorized snapshot; no historical privileged replay.
- A pre-upgrade SQLite snapshot, integrity check and checksum precede migration 0002. Existing campaigns remain usable.
- Browser canvas stays mounted and keeps camera state across token updates; no full-scene reload on each movement.
- Keep all 179 feature IDs and do not claim a playable P0 release. Every update includes a quick cumulative build overview.

## Review focus

Concurrent moves and duplicate IDs; snapshot/event ordering and slow receivers; hidden-token updates/re-hide; cross-campaign/expired/revoked sessions; migration rollback/backup; tab identity changes and pending-command reconnects; camera preservation and late texture loads.
