# Build0.0.12 security boundaries

The host owner is trusted. Players, network requests, invitation holders, browser content and uploads are untrusted. Assets to protect: credentials, sessions, campaign membership, private documents/art and the host filesystem.

Implemented defenses: Argon2id passwords; random 256-bit session/invitation tokens with SHA-256 hashes stored in SQLite; 8-hour sessions with server revocation; HttpOnly/SameSite=Strict cookies; exact Host and Origin checks plus custom mutation header; 16 KiB JSON limit; deny unknown role/request fields; per-peer auth attempt limits (10/minute, bounded 1024 buckets); at most two password operations concurrently; DM-only management APIs; member-scoped reads; SQL-filtered private documents and protected demo/uploaded media. Structured errors do not expose SQL or secrets. Logs contain startup address and generic database failure messages only.

Default loopback startup is deliberate. LAN HTTP does not encrypt credentials, cookies or campaign data. Use it only on a trusted private network. This build rejects public/wildcard binds and does not support internet TLS/proxy trust. Never disable Defender or open a public router port to use this foundation.

CSP disallows remote scripts, objects, framing and eval; Pixi uses its official eval-free compatibility module. User content is plain text rendered through React, never raw HTML. Camera/microphone/geolocation permissions are disabled because A/V is not implemented.

Residual limits: entire demo map bytes can be inspected by authorized viewers; no protected tile delivery. Revocation prevents subsequent API reads, but cannot erase data someone already downloaded; live subscribers reauthorize and clear projected state on revocation, while HTTP/session refresh remains a secondary check. Reconnect never receives privileged historical snapshots. Uploads accept only decoded PNG/JPEG/WebP with matching sniffed MIME; source names never form paths. Canonical RGBA PNG output removes metadata/trailing bytes. Limits:8MiB input,4096px per side,16MiB output, two concurrent uploads,10-second body deadline; image decoder allocation hint128MiB (not a process memory guarantee). Per campaign:32 assets/100MiB,8 scenes/100 tokens. SVG/HTML and foreign asset references are rejected. Downloads stream from disk with no-store/nosniff. Imports/macros/plugins remain absent and require their own validation/isolation. Account recovery, password reset, rotating sessions and per-user session administration remain future work.

Automated evidence: `crates/server/tests/foundation.rs`, `cases/security.rs`, `cases/live.rs` and the three-context browser suite. WebSockets additionally require the exact allowed Origin, current session/member and hearth.v1 negotiation. Every token command rechecks authority in its write transaction, enforces safe coordinates/revisions, and commits a dedupe receipt before publication. Players receive only projected token deltas or an opaque cursor. A token event must have belonged to a public scene at commit time and still be visible at delivery; later activation cannot replay private draft history. REST authorization and projection share a consistent read snapshot. Scene activation/concealment sends fresh filtered snapshots. Asset permission follows the active shared scene; authorization at request time cannot retract an image already sent or in flight. Bounded sockets/frames/rates/history/timeouts are enforced; whole-image confidentiality and production TLS remain out of scope.

The broader threat catalog in the master plan remains mandatory as relevant subsystems arrive. This is not a completed production security review or a released P0 gate.

Actors: only DM DTOs include private notes/grant rosters. Owners may edit ordinary fields but cannot change portrait/private notes/visibility/permissions or delete/link. Observers read. All writes reauthorize membership/grants in the command transaction; linked-token control follows current owners and actorId is null when unreadable, including queued deltas. Protected portraits use current readable actor references. Scene expectedName and actor expectedVersion prevent stale form overwrites. Snapshot outbound budget512KiB is bounded; input16KiB and deadlines remain. Previously downloaded bytes cannot be recalled. No full rules/portable-host/security certification is claimed.

Manual fog is authoritative for token snapshots/REST/deltas, player destinations and token-derived media references. Projection and access share a SQLite read snapshot; command validation is transactional. Entire footprints must be revealed. Hidden IDs and unknown IDs share an unavailable error. Commit-time tokenWasVisible prevents later reveals replaying hidden preparation; current permission is checked after each awaited send. These internal flags are stripped from frames. Shared/explicitly granted actor sheets and portraits remain separately authorized. An already-started authorized response can finish; covering/revoking prevents future reads, not retrospective knowledge. Player rendering uses an opaque mask and suppresses an uncovered image on graphics initialization failure. Full active background downloads remain the disclosed exception.

Dice0.0.6: pure bounded AST, finite math and secure OS entropy with unbiased rejection; no eval/scripting. Input cannot supply result/roller/time. Roll writes, revision, structural event and receipt commit together. Four immutable scopes are projected in the current authorized read snapshot before REST/WS serialization. Blind results never enter player-roller DTOs/acks/events; self-only excludes other DMs. Cache projections replace on snapshots and clear on revoked access. Independent short-lived rate timestamps preserve10/10second budgets across sockets and history eviction. Retain1000 rolls/latest20 authorized DTOs; maximum actor/grant/token/mask/dice fixture fits512KiB. Private means browser authorization, not encryption against the trusted database host. Current committed history is not an externally verifiable fairness proof.

Review correction: result UUIDs are host-generated using fallible OS entropy, while creation nonces are unique only within(campaign,roller). Global ID collision queries no longer expose existence of private/foreign rolls. Tests reproduce the old creation oracle, then prove the fix preserves old private bytes and accepts independent caller nonces. Dice draft/scope stays mounted at campaign-table level across dock tabs, avoiding an unexpected private-to-public reset. Physical reload starts a new composer with explicit Public labeling.

Chat/selected dice: current membership on every read/write, generic unavailable direct IDs, explicit immutable recipient lists and no implicit DM override. Host-owned message IDs are independent of caller-scoped creation nonces; private/foreign record IDs cannot be probed by nonce creation. SQL filters before history limits; events contain only snapshot markers. Client replaces/clears message caches with authorized snapshots and preserves private composer choices across dock tabs. Message rate timestamps are independent of history and use milliseconds; dice's older K018 precision limitation remains. The physical database owner is trusted, and prior delivered/in-flight authorized data cannot be erased. Participant directory exposes only member IDs/display names/roles. No real user data is used in the requested screenshot.

Combat0.0.9: entries derive from current authorized scene/token/fog projection, linked fields from current actor projection. No hidden placeholders/counts/IDs; filtered current turn is null, while round/version/activity metadata remains observable. Every HP mutation checks expected linked actor identity plus version atomically before changing that actor alone. Snapshot marker history prevents later activation/reveal from replaying secret combat data. Creation nonces are caller/campaign/kind scoped and retained after clear. Maximum combined snapshot now includes32 entries under768KiB. Sidebar localStorage contains geometry/navigation only; private composers remain in memory and identity/campaign boundaries clear them. No new security certification/platform/load claim.

Full-host recovery0.0.10 is an explicit trusted machine-owner privilege. Only current isOwner may inspect receipts/data-folder paths, prepare/download whole-host archives, verify or create isolated copies. A campaign DM without host ownership is denied. Whole backups contain password hashes and all private whispers/rolls/hidden content; normal Chat/dice/document APIs still filter these. Do not describe the new export as hiding data from the machine owner. Files are unencrypted, SHA256 detects corruption rather than provenance, and UI/docs state their private scope.

Raw upload is bounded512MiB/60seconds before extraction, no client paths, one operation permit; streaming64KiB file transfers, strict1MiB manifest/current schema10, DB128MiB, PNG16MiB,4096 blobs/512million pixels. Reject paths/links/trailing bytes/extra schema or triggers/invalid migration checksums/FKs/owner mismatch/missing or corrupt artwork. Generated private candidates never overwrite the live root; startup refuses restore-in-progress markers. Session cookies and unused invites are invalidated only in recovered data. Begun authorized downloads retain ordinary in-flight semantics. No comprehensive crash/platform/load certification is claimed.

Map pings0.0.11 are available only on the current shared, unarchived scene and revealed fog cells. Sender and recipient sessions/memberships plus current scene/fog are checked on publication/delivery; server assigns sender and ping IDs. The queue and per-connection frequency are bounded. They are ephemeral and are not exported or replayed. Existing background-image disclosure and full production/network testing limits remain.


GM drawing commands are server-authorized; scene projections filter GM drawings and shared drawing geometry intersecting unrevealed fog before sending to players. Recovered schema 10 and 11 databases are checked against the corresponding migration history.
