# As-built architecture · Build0.0.12

`crates/domain` defines game-neutral serializable wire documents. `crates/storage` owns initialization, an exclusive data-root lock, SQLite WAL/FK configuration and SQLx migrations. `crates/server` coordinates authentication, membership checks, transactional setup/invite redemption and filtered document/media routes.

Axum serves the compiled React/Vite application from `apps/web/dist` (or `HEARTH_WEB_DIR`). The development Vite proxy forwards HTTP and WebSocket `/api`. TanStack Query holds authorized server responses; local component state holds search/dialog/camera state. Pixi is loaded lazily only when opening a scene, using the official no-eval polyfill to retain the strict script CSP. Camera pan/zoom is entirely local and never mutates campaign data.

The server hashes session and invitation secrets; browsers receive an HttpOnly session cookie. Mutations require the exact configured Origin plus a custom request header. Memberships are queried anew on every campaign route. Authorized read transactions filter private scenes/tokens/journals before serialization. Players see only the active shared scene. Asset downloads require a visible reference there; DM may read their own campaign uploads before placement.

The original demo map and token PNGs are compiled into the service; database records reference named opaque demo asset IDs. Uploaded raster assets are decoded/canonicalized by media.rs, quota-checked and installed as content-addressed PNG blobs under the data root. Large downloads stream from disk instead of allocating a complete image per response. Authoring commands live in authoring.rs and use the existing command transaction/receipt boundary. No cloud storage, external identity, telemetry or third-party runtime requests are required.

Live subscriptions use the `hearth.v1` subprotocol, cookie authentication and exact Origin checks. Typed token commands enter an IMMEDIATE transaction that rechecks session/member/control, validates the base revision, writes token/revision/event/receipt and commits before broadcasting a payload-free notice. Each subscriber projects a small token delta against its current permissions and persisted event-time scene publication; hidden actions advance only an opaque revision cursor. Scene create/activate/conceal instead trigger fresh authorized snapshots, so selection in the DM browser remains local until explicit activation. Fresh transactional snapshots are used on connect/reconnect and missing history. Host-instance IDs and contiguous revisions detect gaps. Bounded socket/message/rate/write limits protect the host.

The browser keeps the Pixi application and local camera mounted across token changes, updating only affected token containers. Per-token abort/texture cleanup prevents late hidden images from returning. An authenticated identity owns its nested protected query cache; identity changes clear it. Revocation clears the live projection and closes the socket. Reconnect uses capped backoff and retries one exact pending request; persisted receipts deduplicate an already accepted command. HTTP/session refresh remains as a secondary authorization check. Session keys are not persisted in client localStorage; high-contrast and non-content workspace layout preferences are stored there. Private drafts/recipient lists remain in memory only.

Both DM and players use the same browser application with server-authorized role-specific views. The DM starts one headless web server and distributes browser invitation URLs. The service remains independent of the DM browser tab; there is no desktop shell, tray UI or native application installer in the product direction. This permanently supersedes the original Tauri proposal (ADR-0002), rather than deferring it. Simplified server distribution/startup and a browser host dashboard are the hosting UX targets.

Further authoring/recovery must extend the existing transactional command/receipt/projection boundary; see the master plan and next tasks. Fluent rendering comes from the local Pixi canvas, separated camera state and efficient scoped deltas; a desktop wrapper is unnecessary for those properties.

actors.rs owns validation, member-scoped observer/owner grants and filtered DTOs; Actors.tsx owns character sheets and explicit stale-form reload. Actor versions are independent of unrelated movement; scene rename uses expectedName. Actor/ACL/link/scene changes use fresh current snapshots. Token deltas reproject actor IDs/control at delivery. Test hosting copies the matched browser build under its temporary root so later rebuilds cannot change a running verification.

## VTT workspace and combat (0.0.9)

WorkspaceShell owns map/sidebar/chrome slots; the typed panel registry and campaign/user-scoped preferences own navigation and layout. WorkspaceWindow provides reusable bounded nonmodal token/combat windows. Feature forms own their state; stable PanelPortal hosts move Combat between dock and window without remounting its inputs. Chat/Dice/Journal remain mounted across navigation; Actors/Combat load lazily and remain mounted after first use. Sidebar/window state never owns the renderer, camera or authoritative documents. Only width/open/panel persist in layout storage. Small screens overlay the sidebar over a full-size canvas.

combat.rs uses the existing authorized transaction, revisions, receipts and current scene/actor projections. All combat events are content-free snapshot markers. Token mutations affecting an encounter use snapshots too, preventing stale names/control/visibility in Combat; deletion reconciles the turn. Actor HP is the sole health record. Fresh combat snapshots replace/clear the browser cache on access loss. Migration0010 adds encounters/combatants/scoped creation nonces; no dependency or alternate transport. See the exact combat contract in docs/superpowers/specs.

## Full-host recovery (0.0.10)

Storage backup/{database,format} validates schema/checksums/references and bounded PNG data, frames an uncompressed archive and retains only generated isolated restore roots. VACUUM INTO chooses the consistent DB cutoff; immutable blobs are enumerated from that snapshot. Temporary ownership/marker guards prevent partial candidates from starting. Restore resets sessions/unused invites transactionally, syncs files/directories, then retains the new root. No migration or live-root overwrite.

Server recovery.rs restricts the operational surface to current isOwner, authenticates before upload and publication, and holds one operation permit through detached work. File downloads retain an Arc owning their temporary directory throughout streaming. One prepared archive/verification and a last-copy receipt live in owner-only memory; verification expires15minutes, prepared downloads end on replacement/restart. BackupRecovery is lazy and independent of the canvas/feature state; File uploads and attachment downloads avoid whole-archive JS buffering. Only this privileged owner surface exposes the host data path/full snapshot. Normal document/Chat/dice projections remain scoped.

Build0.0.11 adds an in-memory broadcast channel for transient pings. Each sender and recipient is checked against current membership and the current revealed shared scene; stale/ineligible messages are discarded. The renderer stores ruler points in scene coordinates, so local pan/zoom does not change distance. Neither feature changes database schema or campaign revision.


Scene drawings are persisted and revisioned by the host. Scene projections omit GM-only shapes and conservatively omit shared shapes touching hidden fog cells. The Pixi renderer places shared drawings under fog and tokens, GM drawings above tokens and both under transient tools.
